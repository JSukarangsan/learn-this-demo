# Summary format

`SKILL.md` says what to read; this says what to write.

This is the **only** copy of these rules. `.claude/skills/refresh-index/check.mjs` used to
carry a second one in a `PROMPT` constant and a banner template, and the skill restated both
by hand — two copies of the same judgment, with a co-edit obligation nobody would remember.
The script no longer summarizes, so there is one writer of generated summaries and one place
its rules live. Keep it that way.

## The banner

Every file in `team/_generated/` opens with this, filled in. No exceptions, and no summary
starts before it:

```
<!-- Generated from {canonical}
     by {author} on {date}.
     Source fingerprint: sha256:{sha256} ({bytes} bytes)
     Do not edit this file. Edit the source, or the manifest entry that points at it. -->

> **Generated file.** Summarized from the {type} owned by {owner}, on {date}.
> Refresh cadence: {refresh}. The source is canonical; if this disagrees with it,
> this is wrong.
```

| Placeholder | Comes from |
|---|---|
| `{canonical}` · `{type}` · `{owner}` · `{refresh}` | the source's entry in `context-manifest.yaml` |
| `{author}` | `/refresh-index` — **never** the pipeline. See below |
| `{date}` | the day the body was last written, not the day it was last checked |
| `{sha256}` · `{bytes}` | the SHA-256 and byte length of the source body you fetched |

**`{author}` is `/refresh-index`, always.** The script cannot write these files any more.
Naming a workflow that didn't run is the exact silent gap the refresh log exists to catch.

**The fingerprint line is not decoration — it is the entire change-detection mechanism.**
`check.mjs` reads it back out to decide whether anything needs doing. Write it
wrong and every future run reports the file as drifted and regenerates it from scratch.
The sources it points at expose no `Last-Modified`, no `ETag` and no `Content-Length`, so
this hash is the only thing standing between the team and a summary nobody can date.

**Never compute the fingerprint yourself. Ask for it:**

```sh
node .claude/skills/refresh-index/check.mjs --fingerprint
```

It prints the line to paste, per source. The obvious alternative —
`curl … | shasum -a 256` — **produces a different digest** and has already caused one false
`CHANGED` in this repo. Two reasons, both invisible until you go looking: these exports
carry a UTF-8 BOM that `fetch().text()` strips and `curl` doesn't, and a size taken with
`String.length` counts characters while the banner says bytes (the H2 doc differs by 17).
A fingerprint that was never going to match reads exactly like a source that keeps
changing.

**`{date}` moves only when the body moves.** If the source changed but nothing the summary
asserts is now wrong, update the fingerprint and leave the date alone — the file was not
rewritten, and claiming it was makes the git history lie about when the content last
changed.

## Writing the summary

- **Under 5,000 characters. Shorter is better.** A context file nobody finishes is worse
  than one that omits something.
- **Keep every number, date, name, target and constraint.** Those are the reason the file
  exists. Drop the narrative around them.
- **Keep anything stated as a rule, a guardrail or a decision** — especially anything
  phrased as what NOT to do, and the reasoning behind it.
- **Keep the caveats.** *"This number moves on cohort mix"* is more useful than the number.
- **Add no analysis, recommendations, or anything not in the source.** You are compressing
  someone else's document, not reviewing it.
- **If the source contradicts itself, say so rather than resolving it.** The contradiction
  is the finding, and picking a side hides it.
- Markdown. Start with a heading. No preamble.

## Rewriting an existing summary

Only reached when the fingerprint says the source moved. **Write the smallest change that
makes the file true again** — the size of the edit should match the size of what moved
upstream, not the size of the file.

| What moved | Do |
|---|---|
| Nothing the summary asserts (typo, reflow, reworded sentence) | Update the fingerprint line only. Leave the body and `{date}` untouched. |
| A number, date, target or rule — and nothing else | Edit those lines in place. Do not regenerate. |
| Sections added or removed, or the source reorganized | Regenerate the body in full. |

**Never regenerate a file just because you fetched it.** Summarizing is non-deterministic —
run it twice on identical input and you get two different files — so a full regenerate on an
unchanged source produces a diff that looks like news and isn't. The middle row of that
table is the common case and the one worth getting right: when one target number moves, the
diff should be one line, and a reviewer should be able to see what changed upstream without
reading the source.

## Note what isn't here

No template for the body. The shape of a summary follows the shape of its source — a table
of cohorts summarizes as a table, a planning narrative as prose under headings — and a
skeleton imposed on both would make one of them wrong. The rules above constrain what
survives compression, deliberately not how it is laid out.
